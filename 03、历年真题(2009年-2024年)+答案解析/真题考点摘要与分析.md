## 一、逐年摘要

### 2009 年下半年

**综合知识**：组成 6 / 操作系统 3 / 数据库 5 / 网络 4 / 安全 3 / 软件工程 18 / 架构 22 / 项目管理 4 / 其他 5 / 英语 5。

- **高频考点**：软件三层划分（系统软件/应用软件）；前趋图的并行与直接/间接制约；数据库需求分析产出数据字典与 DFD；参照完整性 vs 触发器；函数依赖求候选键与无损分解；中断方式与断点保存；嵌入式存储的透明性；串/并转换；网络核心层；物理网络设计；SAN；基准测试；商业智能；EAI；EDI；用户文档；配置项；需求变更策略；迭代增量模型；逆向工程四层次；用例关系；面向对象设计模型；基于构件的开发模型与构件接口；MVC/J2EE；RDBMS 数据分布；系统测试；黑盒测试；架构在生命周期中的关注点；ABSD；架构文档与复审；**架构风格判定**（Windows GUI=事件驱动）；ATAM 的风险点/敏感点/权衡点；安全策略；加密算法；著作权；马尔可夫市场占有率。
- **特色**：架构与软件工程题占比极高；开始出现「用架构风格解释现实系统」的题（Web 服务器、集成调试器、工业机器人、编译器）。
- **案例分析**（5 题，第 1 题必答，其余选答；卷面「每题 15 分」与「满分 75 分」前后矛盾，原文不清）：
  1. **在线交易平台的质量属性**（必答）：1s 响应=性能，信息安全=安全性，10s 恢复=可用性，6 小时加功能=可修改性；每种属性给 2 个架构策略。
  2. **商业情报系统建模**：流程图 vs 数据流图（数据流 vs 控制流）；找 DFD 的漏输入/漏输出；画 0 层图；高质量 DFD 的三条原则。
  3. **宇航嵌入式 TLS 三层栈**：层次职责；VxWorks 类 vs Linux 类 OS 的差异（实时性 vs 隔离）；故障分类与滤波/容错算法。
  4. **定速巡航系统**：面向对象 vs 控制环路风格；两种风格下的构件与计算过程；各自适用场景。
  5. **B2C 系统安全架构**：安全威胁分类；认证方式（用户名/口令、PKI、生物特征）；授权侵犯与审计方案。
- **论文**：基于 DSSA 的软件架构设计与应用；信息系统建模方法；基于 REST 服务的 Web 应用系统设计；软件可靠性设计与应用。
- **点评**：案例全部围绕「质量属性 + 架构风格选型」，是后来所有年份案例题的源头模板。

### 2010 年下半年

**综合知识**：组成 6 / 操作系统 4 / 数据库 5 / 网络 4 / 安全 3 / 软件工程 16 / 架构 24 / 项目管理 5 / 其他 3 / 英语 5。

- **高频考点**：微内核的灵活性与性能代价；文件写回时崩溃的影响；LRU 页面淘汰；页面共享；规范化在数据库设计哪个阶段；关系代数表达式；指令周期取指；存储芯片数量计算；磁盘移臂时间；异步传输条件；三层网络结构；逻辑网络设计；网络生命周期五阶段；多处理机性能公式；门户（EIP）；CRM；共享数据库集成；消息中间件；范围定义的输入；活动定义；需求变更控制；CMM 需求管理 KPA；4+1 视图；螺旋模型；软件开发环境；横向重用；方法模型；工厂方法类图；构件定义与构件开发；CORBA 四构件标准；分布式计算层划分；C/S 数据层放置；输入设计；系统测试类型；ABSD；DSSA；质量属性（可用性/性能/可修改性）；评估与风险点；网络安全漏洞；ARP 攻击；GB 8567；专利与职务作品；盈亏平衡。
- **特色**：软件工程与架构合计约 40 题；嵌入式/实时题（示波器、空调调温器、机器人、语音识别）成组出现。
- **案例分析**：
  1. **KWIC 检索系统**（必答）：主程序-子程序 vs 管道-过滤器，按算法变更、功能变更、数据表示变更、性能四个维度打分；最终选管道-过滤器。
  2. **CRSS 数据架构**：集中式 vs 分布式（局部库 + 缓存、读写分离）；避免单点故障的数据库部署；两种架构下的可扩展手段。
  3. **AUTOSAR 汽车电子基础软件**：两种开发流程谁更符合规范（并发、可迭代）；OS 层次结构；开放式架构的优点与 ECU 三大领域。
  4. **ESB 集成框架**：ESB 四个主要功能；四个需求分别对应的集成方式/架构风格；数据格式转换用适配器模式。
  5. **软件可靠性建模**：串联系统 0.99⁴≈0.96；动态冗余（并联）与 N 版本；检错技术的优缺点、实现与处理方式。
- **论文**：软件的静态演化和动态演化；数据挖掘技术的应用；大规模分布式系统缓存设计策略；软件可靠性评价。
- **点评**：案例开始出现「计算型」题目（可靠性、工期成本），架构题仍以风格对比为主。

### 2011 年下半年

**综合知识**：组成 4 / 操作系统 4 / 数据库 6 / 网络 4 / 安全 3 / 软件工程 16 / 架构 22 / 项目管理 0 / 数学 11 / 英语 5。

- **高频考点**：CISC 与 RISC 对比（微程序 vs 硬布线）；Cache 命中率；虚存页失效的外部地址变换；总线分时共享；OS 两类接口（命令/系统调用）；PV 与前趋图（初值 0）；E-R 三元联系 n:m:p；关系代数；**架构风格判定**（语音识别→黑板、Web 服务组合→解释器、编译器→数据共享）；4+1 视图；ABSD 三基础；质量属性→策略配对；敏感点/风险点/权衡点；模式选型（中介者、命令、责任链）；需求跟踪能力链、SNMPv3、PGP、著作权。
- **特色**：风格三连（50–52）答案多与直觉相反；最大流（22）与资源分配（17）两道运筹；知识产权连考 3 题而项目管理 0 题。
- **案例分析**（5 选 3，第 1 题必答）：
  1. **支付系统架构评估**：13 条需求分质量属性；(c) 敏感点、(k) 风险点、(g) 权衡点；效用树按（重要性，难度）排序。
  2. **反规范化**：3NF vs 冗余模型的取舍；手段是加冗余列、加派生列、水平分割。
  3. **机载总线选型**：FC 与 VME 对比（带宽/延迟/扩展）；ARINC653 分区调度；PowerPC 用 MMU 隔离。
  4. **SOA vs ROA**：数据源异构分散时选 REST（资源由 URI 标识、无状态、统一接口）。
  5. **SOA 安全加固**：对称加密 + MAC、公钥加密 + 签名；RBAC + XACML 的 PAP/PDP/PEP/PIP 四件套。
- **论文**：MDA 在系统开发中的应用（PIM→PSM→代码）；企业集成平台的架构设计；企业架构管理（EAM）；软件需求获取技术。
- **点评**：架构 + 设计模式 + 质量属性三分天下；案例开始从「概念题」转向「选型对比题」。

- **操作系统与计算机组成各 4–7 题**，**网络 2–3 题**，**安全＋知识产权 5 题左右**，**数学 3–5 题**，**专业英语 5 题**。

真正在变的是「新概念题」的比重：

- 2015–2018：嵌入式、系统工程（霍尔三维结构）、运筹学题偏多，像在考「宽基础」；
- 2020：区块链挖矿、电子政务四模式、系统监视工具；
- 2021：数字化转型五阶段、国家信息化六要素、AI 芯片、SoC、SDN；
- 2022：云计算 SPI 三层模型、HarmonyOS 分层、DCMM 数据管理、5G 网络切片；
- 2023：SysML、灰盒测试、A/B 测试、NPU、边云协同。

**含义**：架构类题目靠教材能吃下 70%，但每年有 10–15 分是「当年热点」，只刷真题不跟行业会丢分。

### 3. 案例分析：五个母题，年年换皮

1. **质量属性与架构评估**（最高频，几乎每年第 1 题必答）
   - 考法：给一组 a–k 的需求，让你分到性能/可用性/安全性/可修改性/可测试性里；给两种架构风格让你按维度比较后选型；画效用树，指出敏感点、权衡点、架构风险。
   - 答题模板：先分类（需求→质量属性），再对比（交互方式/数据流/扩展方式/性能），最后落到「本项目选哪个、为什么」。
2. **建模**：DFD + 数据字典、ER 图、UML（用例/类/状态/活动/顺序）、SysML 需求图。考的是「图里填空 + 关系判断（包含/扩展/泛化、聚合/组合）」。
3. **数据库与缓存**：分布式透明性、分片与一致性哈希、主从复制与读写分离、反规范化、Redis 数据类型与缓存击穿/穿透。
4. **架构风格与技术选型**：管道-过滤器 vs 仓库、解释器、Lambda vs Kappa、微服务、边缘计算、数字孪生——本质都是「给场景选架构 + 说清对比维度」。
5. **嵌入式与可靠性**：实时系统特性、错误/缺陷/故障/失效的区分、恢复块与 N 版本、心跳与看门狗。

### 4. 论文：题目每隔几年换一批

- **2009–2014**：架构风格、MDA、SOA、企业集成平台、RUP、软件维护、可靠性、需求工程——「方法论时代」。
- **2015–2019**：架构评估、设计模式、数据访问层、微服务（2016 首现）、无服务器架构（2017）、NoSQL 与体系结构演化（2018）。
- **2020–2023**：云原生、数据分片、湖仓一体、区块链、边云协同、AOP、系统安全架构、多源数据集成、可靠性分析与评价——「分布式与数据时代」。

规律很清楚：**传统题（架构风格、架构评估、企业集成、软件维护）是压舱石，几乎每 3–5 年会轮回一次；新题则紧跟当年技术热点，通常比行业落地晚 1–2 年。**

论文的硬性要求十年未变：摘要 ≤400 字（可分行、不许有图表），正文 2000–3000 字，必须逐一回应三问（项目与角色 / 技术论述 / 落地过程与效果），最后落到「问题与解决」。

### 5. 备考建议（结合本目录的资料）

1. **综合知识**：以近 5 年真题为主，先把「架构与设计 + 质量属性 + 设计模式 + 软件工程」这 50 分吃透；每年新增热点单独做一页笔记（云计算/大数据/安全/新技术），不用深，记概念与适用场景即可。
2. **案例分析**：主攻两类——「质量属性 + 风格对比」和「建模填空」。这两类合起来占 60% 以上。练习时严格计时：90 分钟做 3 题，每题 25 分钟，先做必答题。
3. **论文**：准备 **两个** 项目素材（一个 Web/云原生类、一个数据或嵌入式类），套用 04 目录里 35、36 两份模板；重点准备「云原生 / 微服务 / 数据架构 / 安全」四类题，其余靠素材迁移。
4. **用真题的正确姿势**：上午卷用来「查知识域盲区」，下午卷用来「练答题模板」，论文用来「押题 + 练结构」。三者的复习顺序建议是：案例 → 综合 → 论文。
5. **数据缺口**：2019、2022、2023 只有 OCR 线索，2020 是残缺回忆版，2024 无数据。若要补全，需要能提供清晰版 PDF 或文字版真题。
